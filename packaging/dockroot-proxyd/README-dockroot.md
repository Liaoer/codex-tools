# DockRoot packaging for `codex-tools-proxyd`

This directory wraps the standalone `codex-tools-proxyd` binary so it can run on ASUS Merlin routers through [DockRoot](https://www.kspeeder.com/dockroot.html).

The packaging scope remains intentionally small:

- listen on `0.0.0.0:8787`
- persist `accounts.json` and `api-proxy.key` under a USB-backed `/data`
- expose `/health`, `/v1/models`, `/v1/chat/completions`, and `/v1/responses`
- avoid `systemd`, Tauri UI reuse, and public exposure

## Optional Merlin control panel

If you want to manage the container from the Merlin software center instead of using DockRoot commands manually, use the companion rogsoft package in:

```text
packaging/rogsoft-codexproxyd
```

That plugin adds:

- DockRoot and container status display
- URL and API key display
- default model / effort / audit log level configuration
- `accounts.json` / `auth.json` import from the page
- image pull, start, stop, restart, remove, and key refresh actions
- runtime log, request audit log, and error log viewing

## Directory layout

- `Dockerfile`: multi-stage build for `linux/arm64`
- `docker-entrypoint.sh`: startup guard that requires `/data/accounts.json`
- `scripts/import_auth_to_accounts.py`: helper for turning a portable `auth.json` into a one-account `accounts.json`

## Build the image

Run this from the repository root:

```bash
docker buildx build \
  --platform linux/arm64 \
  -f packaging/dockroot-proxyd/Dockerfile \
  -t <public-image-ref> \
  --push \
  .
```

`<public-image-ref>` means the full image name plus tag that the router will pull later.

Example:

```text
ghcr.io/liaoer/codex-tools-proxyd:latest
```

If you use the Merlin control panel plugin, put this exact same value into the `镜像地址` field.

Notes:

- The builder compiles `src-tauri/proxyd` for `aarch64-unknown-linux-musl`.
- Runtime is `alpine:3.20` with `ca-certificates` and `tzdata`.
- `ENTRYPOINT` is fixed to `codex-tools-proxyd serve --data-dir /data --host 0.0.0.0 --port 8787 --no-sync-current-auth`.
- The image now defaults to router-safe limits:
  - `CODEX_TOOLS_PROXY_MAX_BODY_MIB=16`
  - `CODEX_TOOLS_PROXY_MAX_CONCURRENT_REQUESTS=2`
  - `CODEX_TOOLS_PROXY_LOG_MAX_BYTES=524288`
  - `CODEX_TOOLS_PROXY_MAX_UPSTREAM_BYTES=8388608`

## Prepare `accounts.json`

Preferred input: export an existing `accounts.json` from desktop `codex-tools`.

Fallback: convert a single portable `auth.json` locally.

```bash
python packaging/dockroot-proxyd/scripts/import_auth_to_accounts.py \
  --input /path/to/auth.json \
  --output /path/to/accounts.json
```

Optional label override:

```bash
python packaging/dockroot-proxyd/scripts/import_auth_to_accounts.py \
  --input /path/to/auth.json \
  --output /path/to/accounts.json \
  --label "Router Proxy"
```

The helper rejects non-portable auth exports, including macOS-style `auth.json` files that do not contain embedded `access_token` / `id_token`.

## Prepare the router data directory

The examples below assume your ext4 USB device is mounted at `/tmp/mnt/sda1`.

```bash
mkdir -p /tmp/mnt/sda1/codex-proxyd-data
chmod 700 /tmp/mnt/sda1/codex-proxyd-data
```

Upload `accounts.json` into that directory, then tighten its permissions:

```bash
chmod 600 /tmp/mnt/sda1/codex-proxyd-data/accounts.json
```

## Deploy with DockRoot

Container name is fixed to `codexproxyd`.

```bash
cd /tmp/mnt/sda1/DockRootBin

./DockRoot pull <public-image-ref> codexproxyd
mkdir -p /tmp/mnt/sda1/codex-proxyd-data

./DockRoot run -v /tmp/mnt/sda1/codex-proxyd-data:/data --renew codexproxyd
./DockRoot run -d codexproxyd
./DockRoot ps codexproxyd
```

With the example image above, the pull command becomes:

```bash
./DockRoot pull ghcr.io/liaoer/codex-tools-proxyd:latest codexproxyd
```

Useful follow-up commands:

```bash
./DockRoot stop codexproxyd
./DockRoot rm codexproxyd
```

DockRoot logs are written to:

```text
/tmp/mnt/sda1/DockRootData/codexproxyd/ruri.log
```

Successful startup should include lines similar to:

```text
data_dir=/data
listen=http://0.0.0.0:8787/v1
api_key=sk-...
```

## API smoke tests

On the router:

```bash
curl http://127.0.0.1:8787/health
curl http://127.0.0.1:8787/v1/models -H "Authorization: Bearer $(cat /tmp/mnt/sda1/codex-proxyd-data/api-proxy.key)"
```

From another LAN machine:

```bash
curl http://<router-lan-ip>:8787/health
```

Base URL for OpenAI-compatible clients:

```text
http://<router-lan-ip>:8787/v1
```

## Operational notes

- This setup is LAN-only by default. Do not expose `8787` directly to the public internet.
- DockRoot runs with host-like networking and elevated privileges. Treat the container as trusted code.
- `api-proxy.key` is generated by proxyd on first startup and reused across restarts as long as `/data` is preserved.
- If the router clock is wrong, upstream TLS requests may fail. Check `ruri.log` first.
- Override the packaged resource-limit environment variables only after measuring spare memory and storage headroom on the router.
